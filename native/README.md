# Loom on native (React Native / NativeWind)

Loom's primary outputs are web (`tokens.css` + a React catalog on Tailwind v4). A
consumer without a CSS runtime — React Native via NativeWind, a native Tailwind
config — can't eat `tokens.css`. This folder is the bridge: **one neutral data
artifact + a preset that turns it into your NativeWind vocabulary.**

## The boundary (read this first)

> **Values + vocabulary port. Components do not.**

- **Ports:** every token *value* (colors, spacing, radii, type ramp) and the
  *class vocabulary* built on them — `bg-primary`, `rounded-component`, `h-ch-6`,
  `px-screen`, `gap-group`. A spec written against the web catalog ("the CTA is
  `h-ch-6`, the card is `rounded-card`") reads identically here.
- **Does NOT port:** the web atoms themselves. Their `color × variant` treatment
  is a CSS-custom-property cascade that NativeWind can't resolve at runtime. You
  rebuild components natively (an explicit compound matrix) — keeping only the
  token references. Budget shared = values + vocabulary; budget per-platform =
  the components.

## Two files

| File | What | Source of truth |
|------|------|-----------------|
| `tokens.json` | resolved, engine-neutral token data (colors per mode, type ramp, spacing, radii, sizing, effects) | generated by Loom — `npm run generate` emits it to `generated/tokens.json` |
| `loom-native-preset.js` | reads `tokens.json` → a NativeWind preset (theme + semantic-spacing plugin) + a type-ramp helper | this folder — copy it into your app |

`tokens.json` is regenerated wholesale from `spec/answers.json`; never hand-edit
it. That is the whole point — no more hand-transcribing `tokens.css` into a native
`tokens.js` and watching it drift.

## Install

1. Generate (or copy in) `tokens.json`. From the Loom repo: `npm run generate`
   → `generated/tokens.json`. Copy it next to your `tailwind.config.js`.
2. Copy `loom-native-preset.js` into your app beside it.
3. Wire it into NativeWind:

```js
// tailwind.config.js
const loom = require('./loom-native-preset')(require('./tokens.json'));
// pick a mode explicitly if you don't want the default:
// require('./loom-native-preset')(require('./tokens.json'), { mode: 'light' })

module.exports = {
  content: ['./app/**/*.{js,jsx,ts,tsx}', './components/**/*.{js,jsx,ts,tsx}'],
  presets: [require('nativewind/preset'), loom],
};
```

That gives you `bg-primary`, `text-on-surface`, `rounded-component`, `h-ch-6`,
`w-icon-2`, `px-screen`, `gap-group`, `border-1`, and the rest — the same names
the web output emits.

## The type ramp is data, not utilities

NativeWind has no composite `.text-display-lg` utility (that's a web-only Loom
mechanism). So the ramp ships as data you feed to your `<Text>`:

```tsx
import { loomTextStyles } from './loom-native-preset';
const T = loomTextStyles(require('./tokens.json'));
// T.title.md → { fontSize, lineHeight, fontWeight, letterSpacing, fontFamily }

<Text style={T.title.md}>Heading</Text>
```

Sizes come back as unitless numbers (RN's unit) and `em` letter-spacing is
converted to px against the tier size. Wrap this in a small `Text` atom that maps
a `variant`/`size` prop to `T[variant][size]` and you have the web catalog's type
roles, natively.

## Gotchas

- **Raw color, not a class, for RN-prop APIs.** Some RN props take a color value
  directly (`placeholderTextColor`, `<StatusBar>`), not a className. Read those
  from `tokens.color.roles[mode]` — the preset exposes the same values.
- **NativeWind is Tailwind v3.** `tailwindcss/plugin` (used by the preset) and
  `tailwind-merge` behavior are v3 here, not v4 like the web catalog. The preset
  targets v3 on purpose.
- **One mode at build time.** The preset binds one color mode (default:
  `tokens.$meta.defaultMode`). Runtime theme-switching is a component concern,
  not a config one — both mode maps are in `tokens.json` if you need them.
